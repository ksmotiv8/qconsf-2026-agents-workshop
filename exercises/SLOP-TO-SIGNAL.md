# Exercise: from slop to signal

Writing plain English is a really good way to internalize the quality of
output generated by a coding agent and practice steering it. In this
exercise, you write a LinkedIn post about QConSF with an agent, and
take it from slop to something you would actually post.

The agent can shape the words, but only you know what you saw and why it
matters. So the steps split the work: the agent interviews you, you
approve a brief, and every draft after that has to stick to the brief.

We will save each version as `post-1.md`, `post-2.md` and so on, so you
can compare them as you go.

The most important part is reading what comes back after every step. If
something is off, tell the agent in your next prompt. For example: "Drop
the hashtags," "I never said that," or "Make it half as long." You are the
one deciding what goes out with your name on it.

Not into LinkedIn posts? Take the [Slack track](SLACK.md): the same steps,
written as a Slack message to your favorite teammate.

## What you need

Any one of these will work:

- **Claude Code:** needs a Pro, Max, Team or Enterprise plan, or API
  credits. The free Claude plan doesn't include it.
- **Codex CLI:** works on a free ChatGPT account, with tighter limits.
- **mo, or Claude Code on open models:** no Claude or ChatGPT plan
  needed. Use the coupon code `qcon2026`. See [MOMENTO.md](MOMENTO.md).
- **claude.ai, including the free plan:** writing track only. Turn on
  code execution and upload humanizer as a skill
  ([how](https://support.claude.com/en/articles/12512180-use-skills-in-claude)).
  Run the same prompts in a chat, attach or paste each file a prompt
  names, and save each draft yourself.

For step 5, put 2 or 3 of your own LinkedIn posts (or other short posts
you wrote) in a `samples/` folder. No samples? Skip step 5.

## 1. Just ask

We start with the prompt most people would type:

> Write a LinkedIn post telling people I went to QConSF.
> http://qconsf.com. Save it as post-1.md.

Read it. Which tells from Spot the slop do you see? What did it make up,
or leave blank? Don't fix anything yet. This is our baseline.

## 2. Research the talks

QConSF has almost 90 sessions. Let the agent read all of them and find the
ones that matter to you:

> Research QConSF 2026 for my post. First ask me what I work on and which
> sessions I went to. Then go through every session on
> https://qconsf.com/schedule/nov2026 and read its abstract. Save the 5
> most relevant to me in talks.md, with title, speaker, link, and one line
> on why. Only use what's on the site.

Open the links. Is each talk real, and does the reason hold up? Did it find
one you missed?

## 3. Get interviewed

The agent can't know what you saw. Let it ask:

> Interview me for a short LinkedIn post about QConSF. Read talks.md
> first. Ask up to 3 questions, one at a time, about what you need to
> know to write a post only I could write. Wait for each answer. Then
> write my answers to brief.md, show it to me, and wait for my approval.
> Don't write the post yet.

Answer in your own words. Rough notes are fine. Then read `brief.md`
closely. Is every line true? Does it say who the post is for, and what
you want readers to do, like a link to try? Ask it to fix anything that is off. When the brief is right,
send step 4: that is your approval. Everything after this sticks to the
brief.

## 4. Write from the brief

> Using only brief.md, write a LinkedIn post under 120 words. Lead with
> what I took from it, back it with the moment I saw, and end with a next
> step only if the brief has one. Save it as post-2.md.

Put `post-1.md` and `post-2.md` side by side. What changed? Check each
claim against your brief.

## 5. Add your voice

Next, build a skill that writes like you. Ask for a few habits, not an
essay, and keep only the ones that are really you:

> Read the posts in samples/. Show me up to 3 habits of my writing, each
> with a short quote, and wait for my edits. Then save the habits I
> approve as a skill called my-voice in this project. It should change
> phrasing and structure only, never add facts.

Delete any habit that isn't you before you approve. You don't have to
explain what a skill is: the agent knows where skills go. To find it:

- Claude Code: `.claude/skills/my-voice/SKILL.md`
- Codex: `.agents/skills/my-voice/SKILL.md`
- mo: any of those, or `.mo/skills/my-voice/SKILL.md`

Start a new session in the same folder, so the skill loads, and check it:
run `/skills` in Claude Code or Codex, or `/skill` in mo. Then:

> Using only brief.md, write a LinkedIn post under 120 words. Use
> my-voice. Save it as post-3.md.

Compare it with `post-2.md`. Does it sound more like you? Did it add
anything that isn't in your brief?

## 6. Edit it

Install humanizer, a skill that knows the common AI tells, and use it to
find problems, not to rewrite:

> Install the humanizer skill from github.com/blader/humanizer in this
> project.

Check it loaded with `/skills` (`/skill` in mo). Not listed? In Claude
Code, run `/reload-skills`. In Codex or mo, start a new session in the
same folder.

> Read post-3.md. Quote up to 3 lines that sound stock or repeat a
> point, and suggest a cut or a small edit for each. Use the humanizer
> skill. Suggestions only. Don't write any files.

Skipped step 5? Use `post-2.md`. Now edit it yourself. Read it out loud,
take the suggestions you agree with, cut what you would never say, and
save it as `post-final.md`.

## 7. Cold read

Get a reader that didn't write it. Start a new session, and if you can,
pick a different model. If you only change the model in the middle of a
conversation, the new model sees everything the old one wrote and tends
to agree with it.

- Claude Code: `/clear`, then `/model`. Or start it with
  `claude --model <name>`.
- Codex: `/new`, then `/model`. Or start it with `codex -m <model>`. If
  it offers a new worktree, keep the current folder: your drafts are
  here.
- mo: `/clear`, then `/model <route>`. Or start it with
  `mo --model <route>`.
- Or open the other tool. If you wrote it in Claude, review it in Codex.

Only one model? A fresh session on the same model still helps: it sees
the post, not the conversation that wrote it.

> Read post-final.md as an engineer who follows me. In one sentence, what
> do you think my point is? Then check it against brief.md and quote up
> to 3 places where the point is unclear, a detail isn't backed by the
> brief, or the ask feels unearned. Comments only, don't rewrite it.

Is that the point you meant? Fix what you agree with, by hand.

## 8. Make it stick

You corrected the same things all workshop. Save them so you don't have to
type them again:

> Read brief.md, and compare post-3.md with post-final.md, my own edit.
> Propose up to 5 lines for my memory: facts about me, and rules my
> edits show. Nothing about this one post. Show me before saving.

Skipped step 5? Use `post-2.md`. Delete any line that isn't true of
everything you write. Then:

> Save them to this folder's instruction file: CLAUDE.md for Claude Code,
> AGENTS.md for Codex or mo.

Start a fresh session in the same folder (`/clear` in Claude Code and mo,
`/new` in Codex) and type only:

> Write a Slack message to my teammate [name] about one talk in talks.md.
> Save it as msg.md.

Put it next to `post-1.md`. What did it do that you didn't ask for?

Memory is loaded in every session, so keep it short: who you are and the
rules you keep repeating. How you phrase things stays in your my-voice
skill, which loads only when needed. Want the lines in every project?
Move them to `~/.claude/CLAUDE.md` (Claude Code) or `~/.codex/AGENTS.md`
(Codex).

The agents also keep memory of their own. Claude Code's auto memory is on
by default and saves notes from your corrections; see or turn it off with
`/memory`. Codex memories are off by default; turn them on with
`/memories`. Codex doesn't see what ChatGPT remembers about you. Both
vendors say the same thing: rules that must always apply go in the file
you write. See the [Claude Code](https://code.claude.com/docs/en/memory)
and [Codex](https://learn.chatgpt.com/docs/customization/memories?surface=cli)
memory docs.

## 9. See them side by side, then design it

Build one page with every version next to the prompt that made it, then
redesign it with the frontend-design skill. Both are in
[DESIGN.md](DESIGN.md).

## Done?

Read `post-final.md` one more time. Would you post it as is? If so, post
it.
