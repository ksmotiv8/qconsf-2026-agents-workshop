> Notes: You type an ask. The harness does not rewrite it. It wraps it in context: system instructions, your memory files, the tool definitions, the list of skills, and the conversation so far. The whole thing goes to the model. The model does not touch your machine. It answers with a tool call: read this file, run this command, load this skill. > Notes: Before your prompt ever reaches the model, the harness puts a lot in front of it. A system prompt with identity, rules, and environment details. Tool definitions. Your memory files. The skills list. The conversation so far. Your prompt is the thin slice at the bottom. And it is not sent once. Every turn, every tool call, the harness sends the whole stack again, with the conversation a little longer each time. When it gets too long, the harness compacts the older turns into a summary and keeps going, so what goes over is the current context, not every word ever said. The Codex instructions for GPT-6.2 are about 4,000 words; the latest published claude.ai prompt for Opus 5.5 is about 5,200. They are full of patches for real behavior. GPT-6.2 is told not to invent labels like exact-head checks, which tells you it did. It is told never to repurpose the HOME variable, which tells you it did that too. Claude is told not to curse unless you do, and never to use bullet points when declining, to soften the blow. These patches come and go with each model: GPT-5.5's instructions told it, twice, never to talk about goblins, gremlins, raccoons, or pigeons, and that it is clumsy in the interactive git console. Neither line made it into GPT-6.2. The lesson: every one of these lines is someone correcting the model through context. You can do the same thing with your own memory files. Sources: openai/codex repo, codex-rs/models-manager/models.json; Anthropic's published system prompts at platform.claude.com/docs/en/release-notes/system-prompts.

## 13. Why the repeat is cheap
`prefixcache`

One level down
Every turn resends everything. The model reuses what it already read.

Same as turn 1
Tool result
only the new part
Turn 3
Same as turn 2
Next result
only the new part
New model
mid-conversation
Same as turn 2, but nothing cached
Next result
all computed again
Cached: reusedComputed now
Rule of thumb
Keep the start stable. Change it, and the model reads everything again.

> Notes: One level down from the harness. Every turn, the harness sends the whole conversation again: system prompt, tools, memory files, everything so far. That sounds expensive, and it would be, except the model server caches what it already processed. Here is the trip inside the server. The text is tokenized. The server checks whether the start of the request matches something it already processed, a prefix match. On a hit, it reuses the cached keys and values for that prefix, the KV cache in GPU memory, and only processes the new tokens. On a miss, it runs prefill over every token. Then decode generates the answer one token at a time, reading that cache each step. Prefill is what you wait for before the first token appears, time to first token. So the best prefill is the one you skip. A few things break the match: switching models mid-conversation, since each model has its own cache; changing anything near the start; and waiting long enough for the cache to expire. That's one more reason to start a fresh session for the cold read instead of switching models, and to keep your memory file short and stable. It's also why providers charge less for cached input tokens. This comes from our QCon AI talk on KV caching, if you want the deep version.

> Notes: You have all read text like this. The giveaway is rarely one word. It is the shape: the not-X-but-Y contrast, everything in threes, the question you ask so you can answer it, the same handful of words, a dash in every sentence, explaining what the reader just understood, and the chatbot pleasantries left in. Once you see these you cannot unsee them, and neither can the person you send it to. They stop reading and start discounting. So, how do you stop it? No walls of text: if the model gave you four paragraphs, your reader wanted one. Read before you send: you own every word that goes out under your name. Create signal, not noise: the model makes words cheap, which makes attention the scarce thing. Next you will see this for yourself.
