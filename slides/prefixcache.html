Rule of thumb
Keep the start stable. Change it, and the model reads everything again.
One level down from the harness. Every turn, the harness sends the whole conversation again: system prompt, tools, memory files, everything so far. That sounds expensive, and it would be, except the model server caches what it already processed. Here is the trip inside the server. The text is tokenized. The server checks whether the start of the request matches something it already processed, a prefix match. On a hit, it reuses the cached keys and values for that prefix, the KV cache in GPU memory, and only processes the new tokens. On a miss, it runs prefill over every token. Then decode generates the answer one token at a time, reading that cache each step. Prefill is what you wait for before the first token appears, time to first token. So the best prefill is the one you skip. A few things break the match: switching models mid-conversation, since each model has its own cache; changing anything near the start; and waiting long enough for the cache to expire. That's one more reason to start a fresh session for the cold read instead of switching models, and to keep your memory file short and stable. It's also why providers charge less for cached input tokens. This comes from our QCon AI talk on KV caching, if you want the deep version.
